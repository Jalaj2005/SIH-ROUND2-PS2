# API contract — Module 2 (AI Instructor Copilot) notes

Canonical sources: the technical specification (sections 6–9) and the generated files in this folder
(`scenario.schema.json`, `aar-input.schema.json`, `aar-output.schema.json`, `openapi.json`).
Regenerate with `python backend/scripts/export_schemas.py`. **No canonical path, field name, enum value or
event type was changed.** Everything below is either an additive field or a choice made where the spec was silent.
Please confirm each item with Module 1 (contract lock).

## Endpoints implemented (all under `/api/v1`, instructor-only unless noted)
`POST /ai/scenario-drafts` · `GET /ai/scenario-drafts/{draft_id}` · `POST /ai/scenario-drafts/{draft_id}/revise` ·
`POST /ai/aar` · `GET|PATCH /ai/aar/{aar_id}` · `POST /ai/aar/{aar_id}/review` · `GET /ai/aar/{aar_id}/pdf` ·
`GET /ai/status` (any authenticated user). `/health` in `main.py` is a placeholder for Module 1's.

## Additive response fields (existing fields unchanged)
- Draft response: `version`, `parent_draft_id`, `model_provider`, `model_name`, `warnings`, `created_at`.
- AAR response: `version_count`.

## Decisions where the spec was silent — PLEASE CONFIRM
1. **Draft -> approval hand-off.** The AI module exposes no approve/start/activate route (asserted by a test).
   The review screen edits the draft client-side, then calls Module 1: `POST /scenarios` (status `draft`) ->
   `POST /scenarios/{id}/validate` -> `POST /scenarios/{id}/approve`. There is no AI-side `PATCH` of a draft.
2. **Scenario `id`** is generated by the server when the draft is made and kept stable across revisions;
   Module 1 may keep or reassign it on `POST /scenarios`.
3. **Model-facing schema differs from canonical.** Gemini is asked for `GeneratedScenario` (no `id`, `status`,
   `schema_version`; `event_type` is `communication_failure` with a typed `config`). The server maps it to the
   canonical `Scenario` and forces `status = draft`. `GeneratedAAR` likewise has no scores/ids/timestamps/status.
4. **Shared business rules** live in `app/schemas/scenario_rules.py::validate_scenario`. Module 1's
   `/scenarios/{id}/validate` should call it (or be equivalent). Validation issues use `{field, issue}` (same as spec 8.4 details).
5. **Error codes added**: `AI_NOT_CONFIGURED`(503) `AI_TIMEOUT`(503) `AI_UNAVAILABLE`(503) `AI_RATE_LIMITED`(429)
   `AI_PROVIDER_REJECTED`(502) `AI_INVALID_OUTPUT`(502, after bounded retries; nothing stored) `SESSION_NOT_ENDED`(409)
   `INSUFFICIENT_EVIDENCE`(422, no events and no decisions; model is not called) `AAR_NOT_REVIEWED`(409).
6. **AAR session gateway.** Module 1 supplies `SessionGateway.get_aar_input(session_id, requester) -> AARInput` and raises
   `SessionNotFound` / `SessionNotEnded` / `SessionAccessDenied`; override `app.api.v1.deps.get_session_gateway`.
   Until then `FixtureSessionGateway` serves `app/fixtures/aar_input_sample.json`. Module 1 is responsible for
   checking that the requester may see that session; Module 2 also requires `ended_at` to be non-null.
7. **AAR input is read tolerantly** (unknown extra fields ignored). `metrics` values may be `null` (reported as limitations).
8. **Export gating.** PDF requires status `reviewed` (or `exported`) unless `AAR_REQUIRE_REVIEW_FOR_EXPORT=false`.
   Any `PATCH` after review returns the report to `draft`. A successful PDF download sets status `exported`.
9. **Editable AAR fields**: title, executive_summary, key_observations, strengths, improvement_areas,
   recommendations, evidence_limitations, follow_up_scenario_brief. Edited evidence refs are re-validated against the
   original evidence package. The AI original and every edit are kept as versions (not yet exposed by an endpoint).
10. **`include_individual_feedback`** only changes the prompt (role-level wording by `role_id`); the output schema has
    no separate per-person field, and no names/user ids are ever sent to the model.
11. **Ownership.** Drafts and AARs are visible only to the instructor who created them (others get 404).
12. **Evidence references** are event ids, decision ids, or metric keys exactly as they appear in the AAR input.
13. **Placeholder auth** (`app/core/security.py`): dev/test accept `X-Demo-User-Id` + `X-Demo-Role` headers; any other
    `APP_ENV` returns 401. Module 1 should replace `get_current_user`.
14. **Persistence is deferred.** Drafts/AARs are in an in-memory store (`app/services/ai/repository.py`) because Module 1
    owns `db/models.py` and Alembic. Data is lost on restart. Swap in a SQLAlchemy store with the same methods.

## Environment (additions to `.env.example`)
`AI_PROVIDER` (gemini|mock|disabled) · `AI_TIMEOUT_SECONDS` · `AI_MAX_RETRIES` (hard cap 3) ·
`AI_RETRY_BACKOFF_SECONDS` · `AAR_REQUIRE_REVIEW_FOR_EXPORT`. `GEMINI_API_KEY` / `GEMINI_MODEL` are server-side only.
